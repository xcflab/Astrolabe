# Cyclization Topology Examples

这页专门回答两个问题：

1. **最终给模型的 relative position / cyclic offset 到底长什么样？**
2. **真实跑一次结构预测后，结构是否真的满足这些环化要求？**

## 1. 先讲清楚语义

当前实现分两条路径：

- **canonical 头尾环化**：`cyclization.head_to_tail: true`，或者等价的 `A:1@N <-> A:-1@C`。
  - 语义保持旧行为不变。
  - 对整条链使用 cyclic relative encoding。
  - 如果你把它看成 AF2 的 dense `cyclic_offset`，那么整块 `L x L` 子矩阵都会被改写成一个环形最短路 offset。
  - `head_to_tail: true` 只是 protomer `A` 的简写；如果要环化别的 protomer，请显式写对应的 canonical bond。

- **非 canonical 同链 bond**：例如 Cys-Cys 的 `SG-SG`、或者任意链内 atom-atom bond。
  - 先在 bond 张成的区段 `[lo, hi]` 上构造一个“局部环”的 cyclic local offset。
  - 但不会把整段都写回最终矩阵；只会把**两端窗口**对应的 pair 单元写回。
  - 默认每端窗口宽度为 `3`，可用 `cyclization.offset_window` 全局修改，也可在 `cyclization.bonds[].offset_window` 上单独覆盖。
  - `offset_window = k` 的含义是：bond 两端各取**包含端点在内**的 `k` 个残基；例如 `1-6` 且 `k=3` 时，只改写 `1..3 × 4..6` 及其转置，不会改写整个 `1..6 × 1..6`。
  - 如果使用 `cyclization.encoding.mode: rfpeptide_like`（CLI: `--cyclic-encoding rfpeptide-like`），则把 bond 张成的整个 `[lo, hi] x [lo, hi]` 区间写回，模拟 RFpeptide-style 的全区间局部环编码；此模式不按 `offset_window` 截断。

- **跨链 bond**
  - 只会作为 covalent restraint 交给后端，不会生成 cyclic relative patch。

- **多环 / 多 patch 冲突判定**
  - 按最终 sparse matrix cell 判定，而不是按“端点窗口”的残基集合判定。
  - 两个 bond 可以共享端点窗口残基；只要它们没有试图给同一个 `(residue_i, residue_j)` 写入不同 offset，就允许共存。
  - 如果同一个 matrix cell 被重复写入相同 offset，会去重/等价处理；如果写入不同 offset，则拒绝。
  - 因此，某些天然多环拓扑虽然端点窗口互相靠近，仍可同时使用 linkage-local cyclic offsetting。

实现细节上：

- `AF2` 真正吃的是 dense `cyclic_offset`。
- `AF3 / Chai / Protenix / Boltz` 内部不是先构 dense matrix 再读，而是在各自 `d_residue / final_offset` 离散化前，对同样的 pair 单元做 sparse override。
- 所以下面展示的 dense matrix，可以视作这套语义在 `AF2` 上的**显式物化版本**。

## 2. 配置示例

### 2.1 15-residue 头尾环化

```yaml
cyclization:
  head_to_tail: true
```

### 2.2 20-residue 线性多环（两个 disulfide）

这里用一个 20-mer 线性肽，构造两个彼此独立的局部环：

- `A:1@SG <-> A:6@SG`
- `A:12@SG <-> A:17@SG`

```yaml
seqs:
  A: CGGGGCGGGGGCGGGGCGGG

cyclization:
  bonds:
    - a: { proto: A, pos: 1, atom: SG, aa: C }
      b: { proto: A, pos: 6, atom: SG, aa: C }
    - a: { proto: A, pos: 12, atom: SG, aa: C }
      b: { proto: A, pos: 17, atom: SG, aa: C }
```

### 2.3 20-residue bicyclic peptide

这里把 `bicyclic` 定义为：

- 一条 **head-to-tail** 宏环
- 再加一条链内 **disulfide** 次级环

注意：这个例子里两条环的编码方式并不对称——`head-to-tail` 先给整链提供 dense cyclic base，而 `6-15` 只是叠加一个额外 sparse patch。

示例：

- `A:1@N <-> A:20@C`
- `A:6@SG <-> A:15@SG`

```yaml
seqs:
  A: GGGGGCGGGGGGGGCGGGGG

cyclization:
  head_to_tail: true
  bonds:
    - a: { proto: A, pos: 6, atom: SG, aa: C }
      b: { proto: A, pos: 15, atom: SG, aa: C }
```

## 4. 真实结构验证（Chai / Protenix 实测）

为了避免“只有矩阵，没有结构”的错觉，我用真实后端跑了几个最小实验。

### 4.1 15-mer 头尾环化：满足

运行方式：

- 基于旧版 `smoke_chai` 风格的小 Chai 配置；当前仓库不再维护该固定任务名，
  需要用等价的 Chai 配置文件复现实验。
- `num_trunk_recycles=3`
- `num_diffn_timesteps=50`
- `num_diffn_samples=1`

测得成键距离：

- `A:1@N -- A:15@C = 1.3447 Å`

这个值已经非常接近标准肽键长度，说明这个 15-mer 头尾环化在真实结构里是收住的。

### 4.2 20-mer 线性多环（两个 disulfide）：cheap smoke 不稳定，但多 sample 可找到满足约束的结构

#### 单 sample quick smoke（Chai）

同样使用 `num_diffn_timesteps=50, num_diffn_samples=1`：

- `A:1@SG -- A:6@SG = 5.3377 Å`
- `A:12@SG -- A:17@SG = 6.1657 Å`

这说明**单个 top-ranked cheap smoke 结构并不一定满足双环要求**。

#### 单 sample quick smoke（Protenix）

- `A:1@SG -- A:6@SG = 6.2647 Å`
- `A:12@SG -- A:17@SG = 6.5162 Å`

同样没有收住这两个 disulfide。

#### 直接调用 Chai，多 sample（5 个样本）

用同一组 restraint，改成 `num_diffn_samples=5` 后，至少有一个样本满足双环要求：

- `pred.model_idx_0.cif`
  - `A:1@SG -- A:6@SG = 2.0893 Å`
  - `A:12@SG -- A:17@SG = 2.2273 Å`

这说明：

- **这套 topology 语义本身是可工作的**
- 但对于多环，**单个 cheap smoke 样本不可靠**
- 更稳妥的策略是：多 sample + 事后按实际 bond 距离筛选

### 4.3 20-mer bicyclic（头尾环化 + 一个 disulfide）：满足

仍然用旧版 `smoke_chai` 风格的 cheap 设置：

- `A:1@N -- A:20@C = 1.3091 Å`
- `A:6@SG -- A:15@SG = 2.3142 Å`

这说明“整链 head-to-tail + 一个额外局部环”的 bicyclic 例子，在当前实现和最小 smoke 设置下是可以被真实结构满足的。

## 4.4 这些结果是怎么跑出来的

上面的验证使用了两种方式：

- **CLI quick smoke**
  - 15-mer head-to-tail：使用等价 Chai 小配置运行 `<ht15.yaml>`
  - 20-mer multi-ring：使用等价 Chai 小配置运行 `<multi20.yaml>`
  - 20-mer bicyclic：使用等价 Chai 小配置运行 `<bicyclic20.yaml>`
  - 20-mer multi-ring（Protenix 对照）：使用等价 Protenix 小配置运行 `<multi20_protenix.yaml>`

- **直接调用 Chai，多 sample**
  - 对同一组 multi-ring restraint，直接调用 `chai1.run_inference(..., num_diffn_samples=5)`，并逐个检查输出的 `pred.model_idx_*.cif`。

所以这里的“满足/不满足”是**真实结构测量结果**，不是只看 matrix 语义做的推断。

## 5. 结论

- **15-mer 头尾环化**：语义清晰，结构实测满足要求。
- **20-mer 线性多环**：matrix/patch 语义没有问题，但 cheap 单 sample 推理不稳；需要多 sample 或后筛选。
- **20-mer bicyclic（head-to-tail + 一条 disulfide）**：当前实现下，实测可以满足要求。

如果你后面要讨论“我们到底是不是在设计环肽”，我建议把结论分成两层：

- **表示层**：是的，我们已经把 covalent topology 显式传到了 evaluator/backend。
- **采样层**：对简单环（head-to-tail、单个额外局部环）已经能在真实结构里看到满足；对更难的 multi-ring，还需要更强采样或后筛选，不能仅凭 single cheap smoke 就下结论。
