# Experimental isolated trajectories

`execution.enabled: true` runs each existing repeat in a fresh Python process. The repeat order, seed assignment and optimization loop are unchanged. The default is `false`. While enabled, each trajectory holds a conservative host-local, per-UID lock covering the whole trajectory, including legacy evaluators and mutators. This coordinates only cooperating runtime processes under the same user; it does not reserve a GPU against other users, legacy runs or unrelated applications. It does not select devices, and inherits the caller's device visibility. Resource allocation remains the caller's responsibility.

The JSONL client and CPU executor under `astrolabe.runtime` are experimental building blocks; the existing models do not yet use them. The client keeps one explicitly launched worker resident per client instance and checks its reported identity and PID. Identity values must be independently computed and verified by the worker adapter; the transport cannot establish them itself. Calls are serialized and bounded in bytes; timeout or worker loss produces an outcome-unknown error and is never retried. Large scientific data, safe artifact references, durable ownership and recovery require adapter-specific implementation. There is no persistent cross-session reuse, shared GPU admission, model/compute lease separation or adaptive concurrency yet.

The CPU executor launches fresh CPU-only Python subprocesses with CUDA visibility cleared before interpreter startup. It bounds submitted item bytes and item count, and rejects oversized results. It is not wired into scoring or evaluation. GPU concurrency and batching remain disabled by this implementation; no GPU validation is implied by CPU tests.
